Tools

One file defines every colour; the tools read it or are generated from it

The style lives in style/vellum.json. The matplotlib module and the web module read it at run time. The R theme, the LaTeX package, the CSS variables and the Office colour list are generated from it. A change of colour is made in the generators and regenerated, never in a generated file.

How the files are made

build_palettes.py searches, with a fixed seed, for the lightness of each tone that maximises the smallest colour distance between neighbouring series while keeping 3:1 contrast. make_vellum_json.py builds the tints, deeps, ramps, the diverging scale, the gradients and the dark twin from the result and writes vellum.json. make_assets.py writes the five tool files from it.

Run end to end, the pipeline reproduces the published files byte for byte. That is checked, not assumed: regenerate into an empty folder and compare.

cd generators
python build_palettes.py palettes.json      # the seeded search (about 3 minutes)
python make_vellum_json.py ../style/vellum.json
python make_assets.py ../style/vellum.json ../style
git diff --stat ../style                    # nothing: the files are reproduced exactly

matplotlib

Import the module, call use, and draw with the helpers. use resets the rcParams and sets the fonts (Corbel, then Lato, Segoe UI, DejaVu Sans), the surface, the spines, the grid, the tick style, the colour cycle, the line width and the save options (300 dpi, fonts embedded as Type 42). The helpers are the anatomy as functions, so a figure made with them is in the style without further thought.

import vellum
V = vellum.use("light")            # "dark"; scale=2.2 slides, 2.6 posters

# a paper figure: no title block, the claim goes in the caption
plt.rcParams["lines.linewidth"] = 1.2
fig, axes = plt.subplots(1, 3, figsize=V.size("double"))
for ax, letter in zip(axes, "abc"):
    V.panel(ax, letter, None, unit="beak depth, mm")

# a heat map on a gradient
im = ax.imshow(M, cmap=V.cmap_gradient("lagoon"), vmin=0, vmax=6)
V.heat_gaps(ax, nx, ny)
V.gradient_bar(fig, im, ax, "log10 of deaths", ticks=[0, 2, 4, 6])

# a surface and its twin
ax3 = V.axes3d(fig, rect=(0, 0.02, 0.55, 0.74), labels=("z1", "z2", "w"))
V.surface3d(ax3, Z1, Z2, W, cmap=V.cmap_gradient("lagoon"))

Every matplotlib figure in the gallery is a script in examples/python/ that draws both twins from one function.

R and ggplot2

Source the file, add the theme and the scales, put the claim in labs(title) and the unit in labs(subtitle). The theme removes the y title, the legend and the vertical grid, which is most of the anatomy.

  1. Expand the x axis by about a third on the right so the end labels fit: expansion(mult = c(0, 0.32)).
  2. A highlight: map the series to colour, then values = c(rest = vellum$rule, focus = vellum$tone[2]).
  3. Error bars: geom_errorbar(width = 0, colour = vellum$secondary, linewidth = vellum$thin).
  4. A heat map: geom_tile(colour = vellum$surface, linewidth = 0.4) with scale_fill_vellum_grad("lagoon").
  5. ggplot2 has no 3D device: draw the twin in ggplot2 and the surface with base persp.

LaTeX: pgfplots, TikZ and beamer

Load the package after TikZ and pgfplots and use the names. Tones are vteal … vmoss, tints vtealTint, deeps vtealDeep, neutrals vSurface … vInk; the dark twin adds a D (vtealD). Never mix two families with !: that makes a colour outside the palette.

The vellum axis style sets the bottom axis line only, a horizontal hairline grid, no tick marks, muted tick labels and a frameless legend; its axis title is the unit line, and the claim is set outside the axis in the serif. vellum 3d sets the view, the box and flat shading. Colormaps: vellum lagoon, vellum ember, vellum shore and the single families. TikZ diagrams use vellum box, vellum box tint=<family>, vellum arrow, vellum guide, vellum label and vellum claim.

\node[vellum box tint=indigo] (a) {source\\ the data};
\node[vellum box tint=teal, right=1cm of a] (b) {script\\ draws the figure};
\draw[vellum arrow] (a) -- node[vellum label, above] {reads} (b);

Slides use \vellumbeamer or \vellumbeamerdark: canvas, text, structure in teal, alerts in terracotta, blocks on the card, serif frame titles, no navigation symbols. The talk deck and the A0 poster are both built with it.

The web

vellum.css is the token layer: every colour as a --v-* variable under :root, the dark values under [data-theme="dark"], plus the fonts and the three gradients for legend bars. This site is built on it.

For charts, vellum-web.js reads vellum.json directly and gives the anatomy as SVG helpers: axes with a hairline grid and the unit line, ringed dots, dotted reference lines, endLabels with leaders, a tooltip that leads with the value, and the colour science (OKLCH, colour-vision simulation, ΔE, contrast) that gives the same numbers as the Python generators. Every figure on the interactive page is built with it, in plain JavaScript with no dependencies.

Interactive charts read the tokens at run time, so the dark twin follows the page theme. The static figure is made first; interaction is a layer on top.

import * as V from "./vellum-web.js";

const node = document.querySelector("#co2");
const plot = V.frame(node, { title: "Carbon dioxide rose every year since 1959",
                             subtitle: "Mauna Loa, annual mean", footer: "NOAA GML · co2.js" });
V.responsive(plot, (width, P) => {       // redraws on resize and when the twin flips
  V.clear(plot);
  const s = V.svg(plot, width, 320), g = V.el("g", { transform: "translate(44,28)" }, s);
  const x = V.linear([1959, 2019], [0, width - 140]), y = V.linear([300, 420], [248, 0]);
  V.axes(g, P, { x, y, xticks: [1960, 1990, 2019], yticks: [300, 350, 400],
                 xfmt: V.year, unit: "parts per million", width: width - 140, height: 248 });
  V.line(g, rows.map((r) => [x(r.year), y(r.ppm)]), P.tone[0]);
  V.reference(g, P, { y: y(350), x1: 0, x2: width - 140, label: "350 ppm" });
});

Office, Canva, Excalidraw and Google

PowerPoint and Word: a theme, once

  1. Design → Variants → Colors → Customize. Dark 1 ink 2A2825, Light 1 surface FFFFFF, Dark 2 secondary 5A5650, Light 2 card FAF6EE.
  2. Accents 1 to 6, the tones in slot order: 419BA0 A1644F 415688 806629 AD78A1 567E4D. Hyperlink: 415688.
  3. Fonts: headings Palatino Linotype, body Corbel. Save as Vellum.thmx; a dark theme from the dark rows of the TSV.
  4. In each chart: gridlines E6E0D4 at 0.5 pt, no border, no vertical gridlines, no legend for four series or fewer, text boxes at the line ends, the chart area set to no fill.

Canva: a brand kit

  1. Brand Kit → Colors: the seven neutrals, six tones and six tints from vellum-office.tsv, named by family and step; the status colours in a group named "status, with an icon".
  2. Fonts: Palatino Linotype for headings if the plan allows uploads, otherwise EB Garamond; Lato for the body.
  3. One template per infographic format: headline, three tiles, a figure slot, on the white surface.
  4. Figures are imported as PNGs drawn at the pixel size of the format, never redrawn with Canva's chart tool, which cannot do end labels or rings.

Excalidraw

White background; boxes stroked in secondary #5A5650 at 1 px, filled with the card or a family tint; text in ink at 16 px in the "normal" font, never the hand-drawn one; arrows in secondary, guides dotted in rule #C7C3BD, labels in muted. Highlight boxes take the terracotta tint with terracotta deep text. Roughness 0.

Google Docs and Slides, Excel

The same colours typed from the TSV into the custom colour picker; Lato for the body and EB Garamond or Libre Baskerville for headings, since Google serves no Palatino. Excel tables: header in ink on card, alternate rows in card, lining figures. A chart for a report is drawn by vellum.py or vellum.R from the exported CSV.

Never in any tool: a gradient fill on a shape, slide or text (a gradient fill exists only for the legend bar of a data scale, from the nine stops in the TSV), and Office or Canva 3D charts. A 3D figure in a deck is a PNG exported from matplotlib or R at the size of its slot.
